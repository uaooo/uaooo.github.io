## 基本原理

简单来说就是：程序运行时通过解释操作码（opcode）选择对应的函数（handle）执行。

**这里的虚拟机当然并不是指VMWare或者VirtualBox之类的虚拟机，而是指的意思是一种解释执行系统或者模拟器（Emulator）。**

逆向中的虚拟机保护是一种基于虚拟机的**代码保护**技术。它将基于x86汇编系统中的**可执行代码转换为字节码指令系统的代码**，来达到不被轻易逆向和篡改的目的。简单点说就是将程序的代码转换自定义的操作码\(opcode\)，然后在程序执行时再通过解释这些操作码，选择对应的函数执行，从而实现程序原有的功能。

## 自定义指令解释器

### 构成

1. vm\_start:

虚拟机的入口函数，对虚拟机环境进行初始化



2. vm\_dispatcher:

调度器，**解释opcode，并选择对应的handle函数执行**，当**handle执行完后会跳回这里**，形成一个循环。



3. opcode

程序可执行代码转换成的操作码（学了机组之后能够更好地理解opcode）



在这种情况下，如果要逆向程序，就需要**对整个emulator结构进行逆向，理解程序功能，还需要结合opcode进行分析**，整个程序逆向工程将会十分繁琐。这是一个一般虚拟机结构：

![](/images/VM逆向/QQ_1792852064696.png)

常见的结构有：while\-switch  / if型

### 分析方法

在比赛中，虚拟机题目常常有两种考法：

1. 给可执行程序和opcode，逆向emulator，**结合opcode文件**，推出flag

2. 只给可执行程序，逆向emulator，**构造opcode**，读取flag



拿到一个虚拟机之后，一般有以下几个逆向过程：

1. 分析虚拟机入口，搞清虚拟机的输入，或者opcode位置

2. 理清虚拟机结构，包括Dispatcher和各个Handler

3. 逆向各个Handler，分析opcode的意义

### 实现小型虚拟机

我们通过实现一个简化版的小型虚拟机来加深对虚拟机的认识，语言用的是**C语言**。要想实现虚拟机的话需要完成两个目标：

1. 定义一套**opcode**

2. 实现opcode的**解释器**



### 关键结构体

1. **vm\_cpu**

```C
typedef struct
{
    unsigned long r1;    //虚拟寄存器r1
    unsigned long r2;    //虚拟寄存器r2
    unsigned long r3;    //虚拟寄存器r3
    unsigned char *eip;    //指向正在解释的opcode地址
    vm_opcode op_list[OPCODE_N];    //**opcode列表，存放了所有的opcode及其对应的处理函数**
}vm_cpu;
```

其中r1\-r3是定义的通用寄存器，用来传参或者是存放返回值，eip指向正在解释的opcode的地址。

2. **vm\_opcode**

可以看到上面的`op_list`就是用`opcode`数据类型定义的

```C
typedef struct
{
    unsigned char opcode;
    void (*handle)(void*);
}vm_opcode;
```

> **这里的 ****`opcode`**** 绝对不是指某个英文字母或字符，而是一个数字**（比如 0x01, 0x02, 0xFF）。
> 因为 `int` 通常占 4 个字节，太浪费内存了。虚拟机的操作码不需要那么大，最多 256 种（0\~255）就完全足够了，所以用 `unsigned char`（无符号 1 字节整数）是最合适的。
> 
> 

> `void (*handle)(void*);`\-\-函数指针
> 
> 1. `handle`：这是变量的名字。
> 
> 2. `(*handle)`：加上星号和括号，说明 `handle` 是一个指针。
> 
> 3. `(void*)`：跟在指针后面的括号，代表这是一个函数，并且这个函数接收一个参数，参数类型是 **`void*`**（通用指针，也就是可以接收任何类型的指针）。
> 
> 4. `void`：最前面的 `void` 代表，**这个函数执行完毕后不返回任何值**。
> 
> 连起来读就是： `handle` 是一个指针，它指向一个接收 `void*` 参数，并且没有返回值的函数。
> 
> 

实现了虚拟环境之后就可以开始实现**解释器**了。解释器的功能就是对opcode解析，选择相应的handle函数，并且将相应的参数传递给handle函数，由handle函数来解释执行一条指令。

#### vm\_init

```C
void *vm_init()
{

    cpu->r1 = 0;
    cpu->r2 = 0;
    cpu->r3 = 0;

    cpu->op_list[1].opcode = 0xf2;
    cpu->op_list[1].handle = (void (*)(void *))xor;
 
    cpu->op_list[2].opcode = 0xf5;
    cpu->op_list[2].handle = (void (*)(void *))read_;
 
    vm_stack = malloc(0x512);
    memset(vm_stack,0,0x512);
}
```

#### vm\_start

```C++
void vm_start(vm_cpu *cpu)
{
    /*
    **进入虚拟机**
**    eip指向要被解释的opcode地址**
    */
    cpu->eip = (unsigned char*)opcodes;
    while((*cpu->eip) != 0xf4)//如果opcode不为RET，就调用vm_dispatcher来解释执行
    {
        vm_dispatcher(*cpu->eip)
    }
}
```

#### vm\_dispatcher

```C
void vm_dispatcher(vm_cpu *cpu)
{
    int i;
    for(i = 0; i < OPCODE_N; i++)
    {    
        if(*cpu->eip == cpu->op_list[i].opcode)
        {
            cpu->op_list[i].handle(cpu);
            break;
        }
    }
}
```

调试器的代码实现，构成了一个“**取指\-译码\-执行**”的循环。

- `*cpu->eip`：`eip` 是一个指针，指向当前正在执行的 `opcode` 的地址。前面的 `*` 表示解引用，也就是把 `eip` 指向的那个字节（当前的操作码数值）取出来。

- `if` 判断：如果在第 `i` 个位置找到了和当前操作码匹配的指令（`cpu->op_list[i].opcode`）。

- `cpu->op_list[i].handle(cpu);`：找到之后，立刻调用这个指令对应的处理函数。同时，把当前的虚拟机状态 `cpu` 传进去，让处理函数去干活（比如把 `r1` 和 `r2` 相加，把结果存到 `r3`）。

- `break;`：执行完对应的函数后，跳出 `for` 循环。注意：它跳出循环后，函数就结束了。 那么怎么执行下一条指令呢？通常是在外层还有一个更大的 `while(1)` 循环（或者处理函数内部修改了 `eip` 并再次调用调度器）。

`xor`、`read_`、`mov`分别在模拟异或操作、输入操作、**内存与寄存器互传**

mov指令比较难理解：

```C++
void mov(vm_cpu *cpu)
{
    // 指令结构解析：
    unsigned char *res = cpu->eip + 1;          // 第 2 个字节：寄存器标识
    int *offset = (int *)(cpu->eip + 2);        // 第 3-6 个字节：偏移量 (int 占 4 字节)
    char *dest = vm_stack;                      // 虚拟栈基址

    switch (*res) {
        case 0xe1: // 将内存数据写入 r1
            cpu->r1 = *(dest + *offset); break; 
        case 0xe2: // 将内存数据写入 r2
            cpu->r2 = *(dest + *offset); break; 
        case 0xe3: // 将内存数据写入 r3
            cpu->r3 = *(dest + *offset); break; 
        case 0xe4: // 将 r1 数据写入内存 (注意这里没有 x86 那种 dest, src 的复杂形式，而是硬编码)
        {
            int x = cpu->r1;
            *(dest + *offset) = x; break;
        }
    }   
    cpu->eip += 6;  // mov 指令总共占 6 个字节 (1 + 1 + 4)
}
```

数据决定存入哪个寄存器

虚拟机的外层大循环

1. 首先还原执行指针

```C
*(_QWORD *)(a1 + 16) = &unk_202060;
```

我们在 `sub_CD1` 初始化的时候看到过，**`a1 + 16`** 就是虚拟机的指令指针 **`eip`**。
`unk_202060` 就是虚拟机字节码的起始地址。
这一句的意思是：把 PC 指针拨回起点，准备开始执行第一行代码。

2. 核心循环与退出条件

```C
while ( **(_BYTE **)(a1 + 16) != 0xF4 )
    sub_E6E(a1);
```

`0xF4` 就是这台虚拟机的 `HALT`（停机）指令。相当于汇编里的 `exit` 或 `ret`。只要没遇到它，虚拟机就无限运转下去。

3. 单步执行函数

```C
sub_E6E(a1);
```

```C
unsigned __int64 __fastcall sub_E6E(__int64 a1)
{
  int i; // [rsp+14h] [rbp-Ch]
  unsigned __int64 v3; // [rsp+18h] [rbp-8h]

  for ( i = 0; **(_BYTE **)(a1 + 16) != *(_BYTE *)(16 * (i + 1LL) + a1 + 8); ++i )
```

##### sub\_B5F

```C++
unsigned __int64 __fastcall sub_B5F(__int64 a1)
{
  int *v2; // [rsp+28h] [rbp-18h]
  unsigned __int64 v3; // [rsp+38h] [rbp-8h]

  v3 = __readfsqword(0x28u);
  v2 = (int *)(*(_QWORD *)(a1 + 16) + 2LL);
  switch ( *(_BYTE *)(*(_QWORD *)(a1 + 16) + 1LL) )
  {
    case 0xE1:
      *(_DWORD *)a1 = *((char *)qword_2022A8 + *v2);
      break;
    case 0xE2:
      *(_DWORD *)(a1 + 4) = *((char *)qword_2022A8 + *v2);
      break;
    case 0xE3:
      *(_DWORD *)(a1 + 8) = *((char *)qword_2022A8 + *v2);
      break;
    case 0xE4:
      *((_BYTE *)qword_2022A8 + *v2) = *(_DWORD *)a1;
      break;
    case 0xE5:
      *(_DWORD *)(a1 + 12) = *((char *)qword_2022A8 + *v2);
      break;
    case 0xE7:
      *((_BYTE *)qword_2022A8 + *v2) = *(_DWORD *)(a1 + 4);
      break;
    default:
      break;
  }
  *(_QWORD *)(a1 + 16) += 6LL;
  return __readfsqword(0x28u) ^ v3;
}
```

- `0xE1`：把栈上 `[偏移量]` 处的数据读入 r1。

- `0xE2`：把栈上 `[偏移量]` 处的数据读入 r2。

- `0xE3`：把栈上 `[偏移量]` 处的数据读入 r3。

- `0xE5`：把栈上 `[偏移量]` 处的数据读入 r4。

- `0xE4`：把 r1 的值写回栈上的 `[偏移量]` 处。

- `0xE7`：把 r2 的值写回栈上的 `[偏移量]` 处。

