跟AI学的 第一次尝试动态脱壳 是在创宇杯的tea中尝试的

“静态脱壳”看的是文件（死物），而“动态脱壳”抓的是程序运行时的内存（活物）。

当文件在硬盘上的状态被故意伪装、加密、甚至破坏时，静态工具就会瞎火；但只要程序要运行，它就必须在内存里“卸下伪装”，这时动态脱壳就是唯一的杀招。

## 使用场景

1. 遇到“魔改壳”或“自定义壳”（创宇杯的tea）

- 情况：作者改了标准的 UPX 特征（WCP\! 和节名），甚至删除了 `$Info` 头。普通的 `upx -d` 直接被骗过，报错退出。

- 为什么动态能解决：不管你把壳的名字改成什么，只要你还要运行，底层的解压算法依然要把代码解压到内存里。我们不需要去逆向那个壳的算法，只需要“等它解压完，进去抓现行”（在 OEP 处 Dump）。

2. 商业强壳（VMP、Themida、Enigma 等）

- 情况：这些壳在运行前会疯狂地检测你是否在用调试器，代码被虚拟化，IAT 被完全加密，甚至用到了自修改代码（SMC）。

- 为什么动态能解决：它们虽然静态极其恶心，但不管怎么加密，最终 CPU 还是要执行解密后的真实指令。动态调试配合 ScyllaHide 等反反调试插件，在它运行到 OEP 的那一刻抓取内存，依然是目前最通用的脱壳思路。

3. IAT 被“动态重建”的程序（你这次也碰到了）

- 情况：程序文件里的导入表（IAT）是空壳或者被加密的。

- 为什么动态能解决：壳在运行时调用了 `LoadLibraryA` 和 `GetProcAddress`，把真正的 API 地址填进了内存。Scylla 正好在内存里把它们“拍个照”，反向推导出它调用了哪些 DLL 的哪些函数，完美修复 IAT。

4. 静态脱壳导致 PE 头损坏（你之前遇到的“脱壳了但 IDA 全是空白”）

- 情况：你用 `upx -d` 看似脱壳成功了，但因为文件有 Overlay（附加数据）或者结构被破坏，生成的 PE 头是坏的（比如 `raw size = 0`）。

- 为什么动态能解决：内存里的程序是 Windows 加载器严格按照 PE 规范加载的，内存布局永远是对的。Scylla 直接“按图索骥”把内存抓下来，不需要去修复那个被破坏的硬盘头。

5. 没有现成脱壳工具的新壳/小众壳

- 情况：你拿到一个冷门壳，全网没有解壳脚本。

- 为什么动态能解决：任何一个壳，只要它的目的是把原始程序释放出来执行，它最终必然会跳向 OEP。我们只要在“写内存”（`VirtualProtect` 等）和“调用 API”（`LoadLibrary`）下断点，顺藤摸瓜找到 OEP，就能用通用方法把它扒光。

## 步骤

第一步：呼出 Scylla

- 快捷键 `Ctrl + I`，或者在 x64dbg 菜单栏 `插件` \-\> `Scylla`。

第二步：确认 OEP

- Scylla 弹窗后，检查最上方的 `OEP` 框。如果里面是 `00007FF6266F13F0`（你当前的地址），说明正确。如果为空，手动填进去。

第三步：自动搜索 IAT（导入表）

- 点击 `IAT Autosearch` 按钮。

- 如果弹窗提示“高级和普通搜索结果不同”，选 “是\(Y\)”。

- 如果弹窗提示“IAT found”并给出了地址和大小，点 “确定”。

- *原理：Scylla 正在内存里寻找哪些地方被系统填入了 API 地址。*

第四步：获取导入函数

- 点击 `Get Imports` 按钮。

- 此时下方列表会显示出从 `kernel32.dll` 等库引入的函数名（绿色字体）。哪怕有少量红字（比如你遇到的 5 个 Invalid），通常也不影响大局。

第五步：Dump（转储内存）

- 点击右侧的 `Dump` 按钮。

- 它会让你保存一个文件，随便命名，比如 `tea_dump.exe`。（这一步是把内存里的镜像原样抠出来）。

第六步：Fix Dump（修复转储文件）—— 最关键的一步！

- 点击右下角的 `Fix Dump` 按钮。

- 在弹出的文件选择框中，选中你刚才保存的那个 `tea_dump.exe`，点打开。

- 如果左下角日志出现绿色的 `Import Rebuild success`（导入表重建成功），恭喜你，脱壳大功告成！
