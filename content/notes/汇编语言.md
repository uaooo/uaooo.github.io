## 寄存器和内存

### 内存操作方式

1. “间接寻址”是编程语言里指针（Pointer）的底层体现。

将寄存器esi中的值读出来当作地址 去这个地址里取值赋值给寄存器eax

> 如果写成 `mov eax, [esi]`：
> 
> 1. CPU 读取寄存器 `esi` 里的值（假设是 `0x12345678`）。
> 
> 2. CPU 把 `0x12345678` 当作内存地址。
> 
> 3. 去内存地址 `0x12345678` 的地方取出 4 个字节的数据。
> 
> 4. 把取出的数据放进寄存器 `eax`。
> 
> 

中括号 `[ ]` 里的东西，永远代表“内存地址”

2. `mov [esi], eax`的意思是把 `eax` 里面的数据（123），写到 `esi` 记录的那个内存地址（0x0040A000）里去。



```Assembly language
mov esi, [rbp-8]    ; 把局部变量（比如一个指针）拿出来，放到 esi
mov eax, [esi]      ; 间接寻址：顺着 esi 这个地址，把里面的值取出来
add eax, 1          ; 值加 1
mov [esi], eax      ; 把加完的值写回去
```

即

```Assembly language
int *p = &some_var; // 对应 mov esi, [rbp-8]
*p = *p + 1;        // 对应中间的三条指令
```

## 汇编指令

### 数据传送指令

#### Mov

MOV指令用于将数据从一个位置复制到另一个位置。

```Assembly language
; Intel语法示例
mov eax, 123          ; 将立即数123传送到EAX寄存器
mov ebx, eax          ; 将EAX寄存器的值传送到EBX寄存器
mov [esi], eax        ; 将EAX寄存器的值传送到ESI指向的内存地址
mov eax, [ebx+4]      ; 将EBX+4地址处的值传送到EAX寄存器
```

#### Lea

LEA指令用于计算地址并加载到寄存器中，常用于地址计算。

```Assembly language
; LEA指令示例
lea eax, [ebx+ecx*4]  ; 计算EBX+ECX*4的地址并加载到EAX
lea esi, [ebp-8]      ; 计算EBP-8的地址并加载到ESI
```

乍看下来 lea好像和mov差不多 但是

**`mov`**** 是去内存里“取/存数据”，而 ****`lea`**** 根本不访问内存，它只是在计算。**

**差别：是否带内存访问？**

对比：

> - `mov eax, [ebx+ecx*4]`
> 
>     - 动作：算地址 \-\> 访问内存 \-\> **取出数据**。
> 
>     - C 语言：`eax = *(int*)(ebx + ecx*4);` （**解引用**，取内存里的值）
> 
>     - 结果：`eax` 拿到的是**内存里的数据**。
> 
> - `lea eax, [ebx+ecx*4]`
> 
>     - 动作：算地址 \-\> 把地址交给 `eax`。（全程没有去碰内存）
> 
>     - C 语言：`eax = ebx + ecx*4;` （仅仅是算个加减法）
> 
>     - 结果：`eax` 拿到的是**算出来的地址数值本身**。
> 
> 

### 算数运算指令

#### add/adc

加法指令

```Assembly language
; ADD指令示例
add eax, ebx          ; EAX = EAX + EBX
add eax, 10           ; EAX = EAX + 10
add [esi], eax        ; [ESI] = [ESI] + EAX   是地址里面的值加上 eax 的值

; ADC指令示例（带进位加法）
adc eax, ebx          ; EAX = EAX + EBX + CF
```

#### sub/sbb

减法指令

```Assembly language
; SUB指令示例
sub eax, ebx          ; EAX = EAX - EBX
sub eax, 5            ; EAX = EAX - 5

; SBB指令示例（带借位减法）
sbb eax, ebx          ; EAX = EAX - EBX - CF
```

#### mul/imul

乘法指令

```Assembly language
; MUL指令示例（**无**符号乘法）
mul ebx              ; **EDX:EAX** = EAX * EBX

; IMUL指令示例（**有**符号乘法）
imul eax, ebx        ; EAX = EAX * EBX
imul eax, ebx, 10    ; EAX = EBX * 10
```



```Assembly language
mul ebx              ; **EDX:EAX** = EAX * EBX
```

注意：32 位的寄存器，装不下两个 32 位数相乘的结果。

所以 CPU 设计了用 **`EDX`****（高 32 位）和 ****`EAX`****（低 32 位）合体，拼成一个 64 位的结果。**

**隐式的被乘数（默认藏了一个 EAX）**

`mul` 指令的格式是 `mul 乘数`。但发现指令里只有一个操作数（图中的 `ebx`）

其实是被乘数被硬编码默认在 `EAX` 中。 不需要写出来。

#### div/idiv

除法指令

```Assembly language
; DIV指令示例（**无**符号除法）
div ebx              ; EAX = EDX:EAX / EBX, EDX = 余数

; IDIV指令示例（**有**符号除法）
idiv ebx             ; EAX = EDX:EAX / EBX, EDX = 余数
```

注意事项与乘法相同

### 逻辑运算指令

#### **and、or、xor、not**

位运算指令

```Assembly language
; AND指令示例
and eax, ebx         ; EAX = EAX & EBX
and eax, 0xFF        ; EAX = EAX & 0xFF

; OR指令示例
or eax, ebx          ; EAX = EAX | EBX
or eax, 0x80         ; EAX = EAX | 0x80

; XOR指令示例
xor eax, ebx         ; EAX = EAX ^ EBX
xor eax, eax         ; EAX = 0（清零操作）

; NOT指令示例
not eax              ; EAX = ~EAX
```

学了数电和机组可以对这个位运算有更好的理解

#### shr、shl、sar

移位指令

```Assembly language
; 左移指令
shl eax, 1           ; EAX = EAX << 1
shl eax, cl          ; EAX = EAX << CL

; 右移指令
shr eax, 1           ; EAX = EAX >> 1（逻辑右移）
sar eax, 1           ; EAX = EAX >> 1（算术右移）
```

- 逻辑右移（`shr`）：最高位一律补 0。（把数据当成无符号数）

- 算术右移（`sar`）：最高位补符号位（正数补 0，负数补 1）。（把数据当成有符号数，保留正负号）

> 假设寄存器里有一个 8 位的数据 `11111000`（这是 \-8 的补码，最高位 1 代表负数）。我们把它右移 1 位：
> 
> - 逻辑右移 `shr 1`：
> 最高位直接强行补 0。
> 结果变成 `01111100`（十进制的 124）。
> 数据符号变了，从 \-8 变成了正数！
> 
> - 算术右移 `sar 1`：
> 最高位原来是 1（负数），所以补 1。
> 结果变成 `11111100`（十进制的 \-4）。
> 相当于做了除以 2 的运算，保留了负号。
> 
> 

### 比较和跳转指令

**比较和跳转指令用于实现程序的控制流，是汇编语言中实现条件判断和循环的关键。**


#### 跳转指令

jmp、je、jne、jl、jg、jz、jnz

```Assembly language

```

### 基本运算对照

#### 加法运算

C 语言：

```C
int add(int a, int b) {
    return a + b;
}
```

汇编语言：

```Assembly language
; 函数序言
push    ebp
mov     ebp, esp

; 函数体
mov     eax, [ebp+8]    ; 获取参数a
add     eax, [ebp+0Ch]  ; 加上参数b，结果存在EAX中

; 函数尾声
pop     ebp
retn
```

##### 寄存器

要理解这个一整块的汇编语言 首先要对各个寄存器有一定的了解：



```Assembly language
push ebp        ; 把调用者的 ebp 存起来（保护现场）
mov ebp, esp    ; 让 ebp 指向当前栈顶
```

在 32 位系统中，参数是通过栈传递的。假设我们写了一个 C 函数 `int add(int a, int b)`，调用它时：

1. 调用者先把参数 `b` 压入栈，再把参数 `a` 压入栈。（从右向左压栈）

2. `call` 指令执行，把返回地址压入栈。

3. 进入函数，执行 `push ebp; mov ebp, esp`

此时 栈的布局变成：

##### 为什么只有ebp需要push和mov？

> - `push ebp`（保存上一层的图纸）：
> 你现在的函数是被别人（调用者）调用的。调用者也有自己的地基（它的 `ebp`）。你直接盖房子会把人家的地基建在底下，所以你必须先把人家原来的 `ebp` 存到栈里（`push`），等你的房子盖完拆掉时，再还给人家。
> 
> - `mov ebp, esp`（划定自己的地基）：
> `esp` 是动态的栈顶指针（像挖土机的铲子，随着压栈弹栈不停移动）。此时 `esp` 这个位置就是新函数栈帧的起点，但它一直在动。**我们把 ****`esp`**** 的值赋给 ****`ebp`****，这就相当于在图纸上画了一条固定的基准线。以后不管 ****`esp`**** 怎么上下浮动，我们都能通过 ****`[ebp-4]`****、****`[ebp-8]`**** 精确定位局部变量，通过 ****`[ebp+8]`**** 找到参数。**
> 
> - `pop ebp`（拆房子，恢复上一层的地基）：
> 函数结束时，执行`pop ebp`，把之前保存的旧 `ebp` 弹出来重新装回 `ebp` 寄存器。这样我们就“退”回了调用者的地盘。
> 
> 

`eax` 是通用寄存器。在 x86 的 ABI（应用二进制接口）约定里，寄存器被分成了两类：

- 调用者保存（Caller\-saved）：`eax`, `ecx`, `edx`。

- 被调用者保存（Callee\-saved）：`ebx`, `esi`, `edi`, `ebp`, `esp`。

> `eax` 被当成了一个草稿纸，随便写随便算。最后算完了，根本不需要 `pop eax`。因为 x86 调用约定规定了：函数的返回值必须放在 `eax` 寄存器中。
> 
> 所以，`eax` 不需要 `push` 和 `mov` 来建立什么“基准”，它直接承担了“算盘”和“返回值”的双重角色。它天生就是用来被覆盖的。
> 
> 

#### 条件判断

C 语言：

```C
int max(int a, int b) {
    if (a > b) {
        return a;
    } 
    else {
        return b;
    }
}
```

汇编语言：

```Assembly language
; 函数序言
push    ebp
mov     ebp, esp

; 比较a和b
mov     eax, [ebp+8]    ; 获取参数a
cmp     eax, [ebp+0Ch]  ; 比较a和b
jg      short loc_401010 ; 如果a>b，跳转到loc_401010

; a <= b的情况
mov     **eax**, [ebp+0Ch]  ; 返回b
jmp     short loc_401015

; a > b的情况
loc_401010:
mov     **eax**, [ebp+8]    ; 返回a

loc_401015:
pop     ebp
retn
```

调用约定（Calling Convention）：

在 x86（32位）架构中，约定俗成为：函数的返回值必须放在 `eax` 寄存器里。

### 循环结构对照

#### for循环

C 语言：

```C
int sum(int n) {
    int result = 0;
    for (int i = 1; i <= n; i++) {
        result += i;
    }
    return result;
}
```

汇编语言：

```Assembly language
; 函数序言
push    ebp
mov     ebp, esp
sub     esp, 8          ; 分配局部变量空间

; 初始化
mov     dword ptr [ebp-4], 0  ; result = 0
mov     dword ptr [ebp-8], 1  ; i = 1

; 循环开始
loc_401010:
mov     eax, [ebp-8]         ; 获取i的值
cmp     eax, [ebp+8]         ; 比较i和n
jg      short loc_401025      ; 如果i>n，跳出循环

; 循环体
mov     eax, [ebp-4]         ; 获取result
add     eax, [ebp-8]         ; result += i
mov     [ebp-4], eax         ; 保存result

; 循环增量
inc     dword ptr [ebp-8]    ; i++
**jmp     short loc_401010     ; 跳回循环开始**

; 循环结束
loc_401025:
mov     eax, [ebp-4]         ; 返回result
mov     esp, ebp
pop     ebp
retn
```

##### pyr

```Assembly language
mov     dword ptr [ebp-4], 0  ; result = 0
mov     dword ptr [ebp-8], 1  ; i = 1
```

`ptr` 是 pointer（指针） 的缩写。

在汇编里，`[ebp-4]` 只是一个内存地址（比如 0x1234）。但是 CPU 在写内存时，面临一个非常实际的问题：一共要写几个字节？

- 写 1 个字节（8位）？叫 `byte ptr`

- 写 2 个字节（16位）？叫 `word ptr`

- 写 4 个字节（32位）？叫 `dword ptr`（double word）

- 写 8 个字节（64位）？叫 `qword ptr`（quad word）

如果写 `mov [ebp-4], 0`，汇编器会报错：“你只给我一个地址，我怎么知道你要写 1 个字节还是 4 个字节的 0？”
所以必须加上 `dword ptr`，告诉汇编器：“把 0 这个 32 位整数（4个字节），写进 `[ebp-4]` 这个内存地址里。”

> 这是现代计算机的“出厂设定”：内存按字节编址（Byte\-Addressable）
> 
> 当我们写 `mov dword ptr [ebp-4], 0` 时，`[ebp-4]` 只是一个起始地址。CPU 根本不知道你要操作几个房间。
> `dword ptr` 就是给 CPU 的指令：“从 `[ebp-4]` 开始，连续操作 4 个字节的内存。”
> 
> 

总结：`dword ptr` 就是用来告诉 CPU，这次**内存操作的数据宽度是 4 个字节。**

##### inc

`inc` 是 increment（自增） 的缩写。

`inc dword ptr [ebp-8]` 完全等同于 `add dword ptr [ebp-8], 1`。

- 它把 `[ebp-8]` 里的值取出来，加 1，再存回去。

- 对应 C 语言就是 `i++` 或者 `++i`。

为什么要专门发明一个 `inc` 指令？

1. 省空间：`inc` 指令生成的机器码比 `add ... , 1` 更短。

2. 不破坏标志位：在某些老 CPU 上，**`inc`**** 不会改变进位标志（CF）**，而 `add` 会。虽然现代编译器优化很智能，但 `inc` 依然是非常常用的底层指令。

### 指针操作对照

#### 指针解引用

C 语言：

```C
int getValue(int *ptr) {
    return *ptr;
}
```

汇编代码：

```Assembly language
; 函数序言
push    ebp
mov     ebp, esp

; 指针解引用
mov     eax, [ebp+8]    ; 获取指针值
mov     eax, [eax]      ; 解引用指针，获取指向的值

; 函数尾声
pop     ebp
retn
```

**`[ebp+8]`**** 永远是函数的第一个参数。**

1. `mov eax, [ebp+8]`

- 把第一个参数（一个内存地址，假设是 `0x1000`）取出来，放进 `eax`。

- 此时，`eax` 的值是 `0x1000`。

2. `mov eax, [eax]`

- 这就是之前的“间接寻址”。

- `[eax]` 的意思是：把 `eax` 里的值（`0x1000`）当成一个地址，去那个地址里把真正的数据拿出来。

- 假设内存地址 `0x1000` 里存的是 `123`。

- 执行完这句，`eax` 的值就变成了 `123`。

- 最后 `retn` 返回，`eax` 里的 `123` 就是函数的返回值。

```Assembly language

; 指针赋值
mov     eax, [ebp+8]    ; 获取指针值
mov     edx, [ebp+0Ch]  ; 获取要赋的值
mov     [eax], edx      ; 将值赋给指针指向的地址

; 函数尾声
pop     ebp
retn
```

## 反汇编技术

#### 反汇编原理

1. 读取二进制文件的机器码

2. 根据指令集规范解析指令格式

3. 将机器码转换为对应的汇编助记符

4. 分析指令参数和寻址模式

```Assembly language
; 机器码示例
55 8B EC 83 EC 10 8B 45 08 03 45 0C 8B E5 5D C3

; 对应的汇编代码
push    ebp
mov     ebp, esp
sub     esp, 10h
mov     eax, [ebp+8]
add     eax, [ebp+0Ch]
mov     esp, ebp
pop     ebp
retn
```

### 静态反汇编技术

#### 函数识别

1. 查找函数序言模式（push ebp; mov ebp, esp）

2. 查找函数尾声模式（mov esp, ebp; pop ebp; ret）

3. 分析调用约定和参数传递

```Assembly language
; 函数序言（Function Prologue）
.text:00401000 push    ebp            ; 保存旧的栈帧指针
.text:00401001 mov     ebp, esp       ; 设置新的栈帧指针
.text:00401003 sub     **esp, 20h       ; 分配局部变量空间**

; 函数尾声（Function Epilogue）
.text:00401020 **mov     esp, ebp       ; 恢复栈指针**
.text:00401021** pop     ebp            ; 恢复旧的栈帧指针**
.text:00401022 retn                   ; 返回
```

#### 控制流分析

1. 识别条件跳转指令（jz, jnz, jl, jg等）

2. 分析跳转目标和条件

3. 重构程序的控制流图

```Assembly language
; 条件分支示例
.text:00401000 cmp     eax, 0
.text:00401003 jz      short loc_401010
.text:00401005 mov     eax, 1
.text:0040100A jmp     short loc_401015
.text:00401010 loc_401010:
.text:00401010 mov     eax, 0
.text:00401015 loc_401015:
.text:00401015 retn
```
