> 在C/C\+\+逆向里，你拿到一个 `.exe`，你知道它是用 MSVC 或 GCC 编译出来的。
> 在Python逆向里，源码 `.py` 经过编译，会变成字节码（Bytecode），然后打包成 `.pyc` 文件，最后可能再被压缩或加密。
> 
> 

出题人利用了Python这种解释型语言的特性，设置了四层套娃：

1. 障眼法层：`.exe`和`.py`是没有任何关键逻辑的，因为真正的逻辑早已被编译成了Python字节码。

2. 序列化层：`.rpyb` 文件是Ren'Py引擎用来加速启动的缓存，用Pickle和Zlib包装。

3. 虚拟机层：里面藏着的是Python的Code Object（字节码），必须用`marshal`读取，用`dis`反汇编才能还原源码。

4. 算法层：极简的单字节异或。

### 扫盲学习

1. **Ren'Py**：这是一个非常有名的、**专门用来做Galgame的开源游戏引擎**。很多独立视觉小说游戏都是用Python写的Ren'Py引擎开发的。

2. **`.rpyb`**** 文件**：这是这篇文章的主角。

    - 在Python和Ren'Py中，**为了游戏启动更快，引擎会把写好的代码预编译成****字节码****，并且序列化压缩成缓存文件，这就是****`.rpyb`****。**

    - **`.rpyc`****：真正的游戏逻辑源码编译后的文件。**

    - `.rpyb`：只是**缓存**（相当于做菜时的备菜），**通常用来加速**。但出题人把关键的Flag解密逻辑藏在了这个缓存文件里！

3. Pickle / Marshal / Zlib：这三个是Python里的工具。`Zlib`是解压缩用的，**`Pickle`****是把Python对象保存成二进制文件的工具**，**`Marshal`****是Python专门用来序列化字节码的工具**。这道题目就是考察怎么用Python代码把这层表皮剥开。

4. Python代码的运行（源码 \-\> 字节码 \-\> 机器码）

5. 在CTF中，如果遇到Ren'Py引擎，需要知道：

- `.rpy` 是源码。

- `.rpyc` 是编译后的脚本。

- `.rpyb` 是启动缓存。
游戏逻辑被编译成了Python字节码（Bytecode），存在`game/cache/bytecode-312.rpyb`里。`.exe`只是一个C\+\+写的启动器，它只负责加载Python解释器，不参与游戏逻辑计算。

6. 什么是 marshal和pickle？

Pickle 是给开发者用的（用来**存游戏存档、字典**），而 marshal 是 Python 内部专用的序列化工具。
它专门用来**把 Python 的 Code Object（代码对象） 序列化成字节流（bytes）**，存进硬盘（比如 `.pyc` 文件或这里的 `.rpyb`）。
 `Value是 marshal.dumps(code_object)`。
对应的逆向操作就是：`code_obj = marshal.loads(value)`。
此时，我们从内存里拿到了一个 Python 的 Code Object（相当于C语言里编译出来的 `.obj` 文件的结构体）。

7. Code Object 里面有什么？

Code Object 是一个**C结构体**，里面有：

- `co_code`：真正的字节码（一堆数字，相当于机器码）。

- `co_consts`：常量表（数字、字符串、甚至嵌套的 Code Object）。

- `co_names`：变量名表。

8. dis 模块（Python 的 objdump）

因为 `co_code` 是一堆给 Python 虚拟机（PVM）看的数字，人类看不懂。
于是 Python 提供了 `dis` 模块。`dis.dis(code_obj)` 就相当于执行了 `objdump -d`。

9. dump：本质是转储

- 内存 Dump。调试程序，把内存里某一时刻的数据原封不动地保存下来，存成文件，这叫 `dump` 内存。

- 在 Python 序列化里：**`pickle.dumps()`**** 或 ****`marshal.dumps()`**。

    - 这里的 `d` 就是 dump。加上 `s` 代表 `string`（转成字节串）。

    - 所以 `pickle.dumps(cache)` 的意思就是：把内存里的 `cache` 对象，按照 Pickle 的规则，“倒”成一串二进制字节流（bytes）。

10. 序列化（Serialization）= 把内存里的“对象”（**包含数据和结构**）转换成“可以保存或传输的字节流”

2. **第2步：反序列化（遭遇 Pickle 崩溃）**

![](/images/创宇杯/QQ_1789783683976.png)

用010 editor 打开刚刚的unpacked bin，发现开头是`80` `05`，这是典型的pickle格式特征

`80` 是 Pickle 协议标识，`05` 是版本号（Python 3\.8\+ 使用的协议 5）。这在 Pickle 里相当于 PE 文件头的 `MZ`。

**`pickle`**** 是 Python 用来把字典、列表、自定义对象变成二进制流的工具**。

- 操作：写代码 `cache = pickle.loads(data)`。

- 问题：程序报错崩溃了！错误提示是 `ModuleNotFoundError: No module named 'renpy'` 或者 `No module named 'pyanalysis'`。

- 原因：这个字典的键（Key）里，包含了类似 `renpy.xxx` 和 `pyanalysis.xxx` 这种类对象。当 Python 反序列化时，*它遇到这些名字，会试图在当前环境里 **`import`** 这些模块来重建对象。但是你的本机根本没有装 Ren'Py 引擎，所以找不到，直接崩溃。*



3. **第3步：救场（SafeUnpickler 登场）**

此时，`SafeUnpickler` 就派上用场了。
它是一个**拦截器（Hook）**。我们不再使用原生的 `pickle.loads`，而是使用我们自己写的 `SafeUnpickler`。

- 防御机制：`pickle` 在底层重建对象时，会调用一个叫 `find_class(mod, name)` 的方法。默认情况下，这个方法会执行 `import(mod)`。

- 我们的操作：我们**重写**这个方法。拦截到 `import renpy` 时，我们不真的去 `import`（因为本地没有），而是**动态创建一个空类**（`type(f"R_{name}", (), {})`），返回给 Pickle 引擎说：“你要的 `renpy.xxx` 类在这里，拿去用吧。”

- 结果：**Pickle 引擎拿到了一个假的空类**，虽然没什么功能，但足以骗过反序列化过程，让它继续往下走。最终，成功拿到了那个包含数据的字典。

```Python
import pickle
import io
import builtins

# 1. 编写反序列化拦截器 
class SafeUnpickler(pickle.Unpickler):
    def find_class(self, mod, name):
        if mod.startswith("renpy") or mod.startswith("pyanalysis"):
            # **遇到 renpy 模块，不 import，直接现场捏造一个空类**
            return type(f"R_{name}", (), {})
        if mod in ("builtins", "__builtin__"):
            return getattr(builtins, name)
        return type(f"S_{mod}_{name}", (), {})

#  2. 读取刚才解压的文件
with open("unpacked.bin", "rb") as f:
    data = f.read()

# 3. 使用 SafeUnpickler 
print("\n使用 SafeUnpickler 再次尝试反序列化...")
try:
    ver, cache = SafeUnpickler(io.BytesIO(data)).load()
    print(f"[*] 版本号: {ver}")
    print(f"Pickle 反序列化成功！字典大小: {len(cache)} 个条目")
    
    # 打印前几个 Key（文件路径），看看里面有什么
    print("\n提取到的文件路径 ")
    for i, key in enumerate(cache.keys()):
        filename = key[2] if len(key) > 2 else "Unknown"
        print(f"  [{i}] {filename}")
        if i >= 15: # 只打印前15个，防止刷屏
            print("  ... (省略更多)")
            break
    
except Exception as e:
    print(f"SafeUnpickler 反序列化也失败了: {e}")
```

4. **第4步：提取代码对象（Marshal ）**

Pickle 反序列化后，我们得到了一个包含 3949 个文件的巨大字典。这就像是把一整个游戏引擎（包含它自带的所有代码库）全部摊开在了你面前。

我们的脚本需要做的是：遍历这 3949 个文件，把它们的**字节码（Marshal格式）还原成代码对象**，然后自动扫描里面的常量表。

```Python
import pickle
import io
import builtins
import marshal
import types
import sys

class SafeUnpickler(pickle.Unpickler):
    def find_class(self, mod, name):
        if mod.startswith("renpy") or mod.startswith("pyanalysis"):
            return type(f"R_{name}", (), {})
        if mod in ("builtins", "__builtin__"):
            return getattr(builtins, name)
        return type(f"S_{mod}_{name}", (), {})

# 读取上一步解压出来的 unpacked.bin
with open("unpacked.bin", "rb") as f:
    data = f.read()

ver, cache = SafeUnpickler(io.BytesIO(data)).load()
print(f"成功加载字典，共 {len(cache)} 个条目。开始遍历搜索核心逻辑...\n")

# 递归搜索函数
def search_suspicious_consts(code_obj, filename):
    # 1. 检查当前代码对象的常量表
    for const in code_obj.co_consts:
        # 如果是嵌套的函数/类，递归深入
        if isinstance(const, types.CodeType):
            search_suspicious_consts(const, filename)
        
        # 2. 寻找可疑的 bytes 常量（异或密文特征：长度长，含不可打印字符）
        elif isinstance(const, bytes):
            # 过滤掉短字节串，过滤掉纯ASCII的普通字符串
            if len(const) > 15:
                # 检查是否含有非ASCII字符（比如 WP 里的 \x1b, \x1a）
                has_non_ascii = any(b < 32 or b > 126 for b in const)
                if has_non_ascii:
                    print(f"[可疑目标] 文件: {filename}")
                    print(f"字节码函数名: {code_obj.co_name}")
                    print(f"密文数据 (bytes): {repr(const)}")
                    print("-" * 50)

# 遍历所有 3949 个条目
for i, (key, value) in enumerate(cache.items()):
    if not isinstance(value, bytes):
        continue
    filename = key[2] if len(key) > 2 else "Unknown"
    
    # 只筛选 .rpy 或 .rpym 文件，跳过纯资源
    if not (filename.endswith('.rpy') or filename.endswith('.rpym')):
        continue

    try:
        # Marshal 加载字节码
        code_obj = marshal.loads(value)
        # 递归搜索
        search_suspicious_consts(code_obj, filename)
    except Exception as e:
        # 可能会因为Python版本不匹配导致 marshal 失败，这里做异常捕获
        pass

print("\n搜索完成！")
```

脚本解释：

- `marshal.loads(value)` 把二进制变成了 `code_obj`（代码对象，相当于 `.obj`）。

- 我们的脚本深入到了 `code_obj.co_consts`（常量表）里。

- 在常量表里，我们发现了一个 `bytes` 类型的常量 `b'OJN\x1b...'`，把它打印了出来。

怎么锁定key和value？

靠**特征过滤**。

*1\.过滤掉 99% 的 renpy/common/ 文件，只看开发者自己写的 game/ 目录*

*2\. 锁定 Value 里的常量：靠数据特征*

在逆向里，我们管这叫启发式搜索（Heuristic Search）。出题人得把**密文放在源码里**而不能把密文放在引擎自带的文件里，只能放在 `game/` 下。密文是加密的，必然是一堆乱码，**必然包含大量不可打印字符**。这就是我们锁定它的依据。

> 这行 `marshal.loads(value)`，就像是用反序列化工具，把那串二进制 `.o` 文件重新还原成了 Python 虚拟机的可执行结构体（Code Object）。
> 这个结构体里面包含了很多东西：
> 
> - `co_code`：具体的虚拟机汇编指令。
> 
> - `co_names`：全局变量名。
> 
> - `co_consts`：常量表（重点！）。
> 
> - `co_filename`：源文件名。
> 
>

现在拿到了字典。字典的格式大概是：

```C
{    (哈希值, 槽位, "game/script.rpy", 模式, 源代码, 行号): b'\x63\x00\x00...' *# 这是一堆二进制字节*}
```

- 解释：`pickle` 是用来序列化数据的（字典、变量）。`marshal` 是 Python 内部专门用来序列化代码对象（Code Object）的。Code Object 是 Python 虚拟机执行的指令集，相当于 C 语言编译出来的 `.o` 目标文件。

- 操作：用 **`code_obj = marshal.loads(value)`****，就把这串二进制还原成了一个 Python 的 ****`Code Object`**** 结构体。这个结构体里有字节码、常量、变量名等。**



5. **第5步：反汇编（dis 登场）**

拿到了 `code_obj`，它相当于一个 `.o` 文件，是一堆杂乱无章的十六进制数字。

拿到了密文：`b'OJN\x1b\x1a\x1c\x1aHULLI\x1dUL\x1c\x1dKU\x1a\x19KOULO\x1cHKJ\x1e\x1dO\x1a@\x19'`

但是还没拿到算法：

```Python
import pickle, io, builtins, marshal, dis

class SafeUnpickler(pickle.Unpickler):
    def find_class(self, mod, name):
        if mod.startswith("renpy") or mod.startswith("pyanalysis"):
            return type(f"R_{name}", (), {})
        if mod in ("builtins", "__builtin__"):
            return getattr(builtins, name)
        return type(f"S_{mod}_{name}", (), {})

with open("unpacked.bin", "rb") as f:
    data = f.read()

ver, cache = SafeUnpickler(io.BytesIO(data)).load()

for key, value in cache.items():
    filename = key[2] if len(key) > 2 else "Unknown"
    if "game/script.rpy" in filename:
        print(f"[*] 开始反汇编目标: {filename}")
        code_obj = marshal.loads(value)
        
        # 关键动作：dis 反汇编（相当于打开 IDA 的图形界面看汇编）
        dis.dis(code_obj)
        break
```

- 操作：调用 `dis.dis(code_obj)`。

- 解释：**`dis`**** 就等于我们的反汇编器（objdump）。它把二进制字节码翻译成人类可读的 Python 虚拟机汇编指令。**

- 注意：在 Python 里，函数是层层嵌套的。如果 `code_obj` 里定义了一个函数 `dec`，那么 `dec` 的代码对象**不会直接在 ****`code_obj`**** 的字节码里，而是作为常量放在 ****`code_obj.co_consts`**** 里**。所以需要写一个递归函数，不停地在 `co_consts` 里翻找，直到找到那个包含 `dec` 逻辑的 Code Object。



6. **第6步：提取算法，解密**

当对找到的深层 Code Object 执行 `dis.dis` 后，我们会在 Python 汇编里看到类似 `LOAD_CONST`（加载常量）、`BINARY_XOR`（异或操作）的指令。
同时，我们会在它的常量表 `co_consts` 里看到一个很长的乱码字节串：`b'OJN\x1b...'`
结合汇编逻辑，猜测它执行的是异或（`^ 128`）。
最后，用 `''.join(chr(b ^ 128) for b in heart)` 写个小脚本，Flag 就出来了。

还原为Ren'Ry源码即：

```Python
heart = b'OJN\x1b\x1a\x1c\x1aHULLI\x1dUL\x1c\x1dKU\x1a\x19KOULO\x1cHKJ\x1e\x1dO\x1a@\x19'
def dec(content):
    return "".join(chr(ord(i) ^ 120) for i in content.encode())
```

逻辑就是：单字节异或 xor 0x78（字符'x' ASCII码值120）

```Python
def tea_decrypt(v0, v1, k, rounds=32):

    for _ in range(rounds):
        v1 = (v1 - ((((v0 << 4) & MASK) + k[2]) ^ ((v0 + s) & MASK) ^ ((v0 >> 5) + k[3]))) & MASK
```

#### 加密算法

复习一下这道题需要使用的一些加密算法

##### AES

**AES 其实就是 Rijndael 在“分组=16 字节”时的特例。**

**这道题用的是 Rijndael 分组 24 字节，所以不是标准 AES。**

不管是 AES 还是 Rijndael，它们的代码都有非常明显的特征：

1. 指纹 1：**S 盒**（Substitution Box）

S 盒是一张 256 字节的表。标准 AES 的 S 盒第一个字节是 `0x63`：

```C
63 7c 77 7b f2 6b 6f c5 30 01 67 2b fe d7 ab 76 ...
```

2. 指纹 2：轮常量 Rcon

AES/Rijndael 的**密钥扩展会用到一组常量**：

```C
01 02 04 08 10 20 40 80 1b 36
```

在汇编里看到这串数字挨着出现，基本就能确认。

3. 指纹 3：**MixColumns 的系数 2、3、9、11、13、14**

加密用 `2` 和 `3`，解密用 `9 11 13 14`。
在反编译代码里会看到类似：

```C
v = mul(a, 2) ^ mul(b, 3) ^ c ^ d;
```

或者一大串异或和左移。这也是 AES/Rijndael 的招牌。

##### CBC

CBC 的特征是异或。加密时：

```C
密文块 = Encrypt(明文块 XOR 上一块密文)
```

即

```C
密文1 = 加密(明文1 XOR iv)
密文2 = 加密(明文2 XOR 密文1)
```

解密时：

```C
明文块 = Decrypt(密文块) XOR 上一块密文
```

在反编译代码里会看到：

```C
for (i = 0; i < n; i += block_size) {    *// 先异或*    
  for (j = 0; j < block_size; j++)        
    tmp[j] = data[i+j] ^ prev[j];    *// 再加密*    
  encrypt_block(tmp, out+i);    *// 更新 prev*    
  prev = out + i;
}
```

看到“先 XOR 再加密，然后 prev 指向刚加密的块”，就是 CBC。

6. CBC加密主循环

```Java
v23 = v14;    // 明文指针
  v24 = 0;      // 计数器
  ...
  do
  {
    // 1. 分配 24 字节给临时变量 v28
    v25 = operator new((unsigned __int64)v14);
    v28 = v25;
    ...
    // 2. 异或操作（CBC 核心）
    for ( i = 0; i != 24; ++i )
      *(_BYTE *)(v28 + i) = *(_BYTE *)(v22 + i) ^ v23[i];
      
    // 3. 调用 Rijndael 加密一块
    sub_140005F00(v14, v22, &v76, &v74, &v72, ...);
    
    // 4. 把加密结果拼接到输出
    ...
    // 5. 更新指针
    v24 += 24LL;
    v23 += 24;
    v22 = v70[0]; // **关键：前一密文指针变成当前密文**
  }
  while ( v24 < v50 - (__int64)v14 );
```

- `for ( i = 0; i != 24; ++i )`：每次处理 24 字节（一个块）。

- `*(v28 + i) = *(v22 + i) ^ v23[i];`：把当前明文块 `v23` 和上一块密文 `v22` 异或。如果是最开始，`v22` 就是前面初始化好的 IV。

- `sub_140005F00`：把异或后的 24 字节丢进去加密。

- `v22 = v70[0];`：更新 `v22`，指向刚加密出来的密文，供下一块异或用。

- `v23 += 24`：明文指针往后走 24 字节。

结论： 这是标准 CBC 模式：`密文 = Rijndael(明文 XOR 上一块密文)`。

### 解密流程

因此 我们的解密流程为

先爆破 token  作用是：

> 我们不知道作者当初用的 token 是什么，但我们知道 VEC 是用某个 token 加密出来的。
> 我们可以爆破这个 token，中了就能**解密 VEC。**
> 
> 

程序设计的加密流程为：

```C
token  →  key/iv  →  加密/解密  →  flag
```

#### Rijndael 需要 key

Rijndael 是一个分组加密算法，它加密/解密时必须有一个**固定长度的密钥。**

- 这道题用的是 Rijndael\-192，密钥长度必须是 32 字节。

- token 是 `"m114514"`，只有 7 字节。

- 长度不对，不能直接用。

所以程序要先做一步“加工”：

```C
key = MD5("VxS9Rm7f" + token + "8gKT_638").hexdigest()
```

MD5 输出 16 字节，转成 hex 字符串是 32 字节。

正好满足 Rijndael\-192 对密钥长度的要求。

token 是原材料，key 是加工出来的真正密钥。

#### CBC 需要 iv

**CBC 模式还需要一个“初始向量”，用来和第一块明文异或。**

- iv 长度必须等于分组长度，也就是 24 字节。

- 程序从 key 里切 24 字节出来当 iv：

```C
iv = key[rem : rem+24]
```

iv 也是从 key 加工出来的。

```Java
输入：VEC（48 字节），token = "m114514"

第 1 步：派生 key 和 iv
   key = MD5("VxS9Rm7f" + "m114514" + "8gKT_638").hexdigest()   // 32 字符
   rem = 114514 % 7
   iv  = key[rem : rem+24]                                      // 24 字符

第 2 步：把 VEC 切成 2 块（每块 24 字节）
   块1 = VEC[0:24]
   块2 = VEC[24:48]

第 3 步：CBC 解密
   明文1 = Rijndael解密(块1) XOR iv
   明文2 = Rijndael解密(块2) XOR 块1

第 4 步：拼起来
   明文 = 明文1 + 明文2 = 48 字节

第 5 步：去掉尾部零填充
   flag = 明文.rstrip(0x00) = 36 字节
```

### Exp

因此分析之后我们就能写出脚本了

```Python
import hashlib
import sys

VEC = bytes.fromhex(
    "c17304e95340b6d51e0adefad6d80c64a1ca5d6365f307f0d82a744d7faa8d"
    "fa8132bbb9fd5f514cb9694ba7263bd1ab")

def _sbox():
    p, q, s = 1, 1, [0] * 256
    while True:
        p = p ^ ((p << 1) & 0xFF) ^ (0x1B if p & 0x80 else 0)
        q ^= q << 1
        q ^= q << 2
        q ^= q << 4
        q &= 0xFF
        if q & 0x80:
            q ^= 0x09
        s[p] = (q ^ ((q << 1) | (q >> 7)) ^ ((q << 2) | (q >> 6)) ^
                ((q << 3) | (q >> 5)) ^ ((q << 4) | (q >> 4)) ^ 0x63) & 0xFF
        if p == 1:
            break
    s[0] = 0x63
    return s

SBOX = _sbox()
INV = [0] * 256
for _i in range(256):
    INV[SBOX[_i]] = _i

def _gmul(a, b):
    r = 0
    for _ in range(8):
        if b & 1:
            r ^= a
        hi = a & 0x80
        a = (a << 1) & 0xFF
        if hi:
            a ^= 0x1B
        b >>= 1
    return r

M2 = [0] * 256
M3 = [0] * 256
M9 = [0] * 256
M11 = [0] * 256
M13 = [0] * 256
M14 = [0] * 256
for _i in range(256):
    M2[_i] = _gmul(_i, 2)
    M3[_i] = _gmul(_i, 3)
    M9[_i] = _gmul(_i, 9)
    M11[_i] = _gmul(_i, 11)
    M13[_i] = _gmul(_i, 13)
    M14[_i] = _gmul(_i, 14)

class Rijndael192:
    """Nb = 6 (24 字节分组); Nk = len(key)//4; Nr = max(Nb, Nk) + 6"""

    def __init__(self, key):
        self.Nb, self.Nk = 6, len(key) // 4
        self.Nr = max(self.Nb, self.Nk) + 6
        w = [list(key[4 * i:4 * i + 4]) for i in range(self.Nk)]
        rcon = 1
        for i in range(self.Nk, self.Nb * (self.Nr + 1)):
            t = list(w[i - 1])
            if i % self.Nk == 0:
                t = t[1:] + t[:1]
                t = [SBOX[b] for b in t]
                t[0] ^= rcon
                rcon = M2[rcon]
            elif self.Nk > 6 and i % self.Nk == 4:
                t = [SBOX[b] for b in t]
            w.append([w[i - self.Nk][j] ^ t[j] for j in range(4)])
        self.w = w

    def _ark(self, st, rnd):
        Nb = self.Nb
        for c in range(Nb):
            word = self.w[rnd * Nb + c]
            for r in range(4):
                st[r][c] ^= word[r]

    def encrypt(self, block):
        Nb = self.Nb
        st = [[block[r + 4 * c] for c in range(Nb)] for r in range(4)]
        self._ark(st, 0)
        for rnd in range(1, self.Nr):
            for r in range(4):
                for c in range(Nb):
                    st[r][c] = SBOX[st[r][c]]
            for r in range(1, 4):
                st[r] = st[r][r:] + st[r][:r]
            for c in range(Nb):
                a0, a1, a2, a3 = st[0][c], st[1][c], st[2][c], st[3][c]
                st[0][c] = M2[a0] ^ M3[a1] ^ a2 ^ a3
                st[1][c] = a0 ^ M2[a1] ^ M3[a2] ^ a3
                st[2][c] = a0 ^ a1 ^ M2[a2] ^ M3[a3]
                st[3][c] = M3[a0] ^ a1 ^ a2 ^ M2[a3]
            self._ark(st, rnd)
        for r in range(4):
            for c in range(Nb):
                st[r][c] = SBOX[st[r][c]]
        for r in range(1, 4):
            st[r] = st[r][r:] + st[r][:r]
        self._ark(st, self.Nr)
        return bytes(st[r][c] for c in range(Nb) for r in range(4))

    def decrypt(self, block):
        Nb = self.Nb
        st = [[block[r + 4 * c] for c in range(Nb)] for r in range(4)]
        self._ark(st, self.Nr)
        for rnd in range(self.Nr - 1, 0, -1):
            for r in range(1, 4):
                st[r] = st[r][-r:] + st[r][:-r]
            for r in range(4):
                for c in range(Nb):
                    st[r][c] = INV[st[r][c]]
            self._ark(st, rnd)
            for c in range(Nb):
                a0, a1, a2, a3 = st[0][c], st[1][c], st[2][c], st[3][c]
                st[0][c] = M14[a0] ^ M11[a1] ^ M13[a2] ^ M9[a3]
                st[1][c] = M9[a0] ^ M14[a1] ^ M11[a2] ^ M13[a3]
                st[2][c] = M13[a0] ^ M9[a1] ^ M14[a2] ^ M11[a3]
                st[3][c] = M11[a0] ^ M13[a1] ^ M9[a2] ^ M14[a3]
        for r in range(1, 4):
            st[r] = st[r][-r:] + st[r][:-r]
        for r in range(4):
            for c in range(Nb):
                st[r][c] = INV[st[r][c]]
        self._ark(st, 0)
        return bytes(st[r][c] for c in range(Nb) for r in range(4))

def derive(token):
    """token 形如 b'W8341' / b'm114514' -> (32 字节 hex 密钥串, 24 字节 IV)"""
    key = hashlib.md5(b"VxS9Rm7f" + token + b"8gKT_638").hexdigest().encode()
    rem = int(token[1:]) % 7
    return key, key[rem:rem + 24]

def decrypt_vec(vec, token):
    key, iv = derive(token)
    rd = Rijndael192(key)
    out, prev = b"", iv
    for i in range(0, len(vec), 24):
        blk = vec[i:i + 24]
        out += bytes(a ^ b for a, b in zip(rd.decrypt(blk), prev))
        prev = blk
    return out

def encrypt_vec(pt, token):
    key, iv = derive(token)
    rd = Rijndael192(key)
    out, prev = b"", iv
    for i in range(0, len(pt), 24):
        x = bytes(a ^ b for a, b in zip(pt[i:i + 24], prev))
        prev = rd.encrypt(x)
        out += prev
    return out

def try_token(token_b):
    pt = decrypt_vec(VEC, token_b)
    if all(32 <= c < 127 for c in pt[:24]):        # 首块 24 字节全部可打印即命中
        return pt
    return None
```

因此 通过这道题 我们应该学会如何看伪代码:

我们需要注意到是：

80% 的伪代码是编译器生成的垃圾（内存分配、异常检查、STL模板），而真正的人类逻辑只有 20%。

1. 识别 C\+\+ STL 的“噪音”

    - `std::string::_M_create`, `_M_dispose` → 字符串的分配和释放。

    - `std::vector` 的 `operator new` \+ `memmove` → 动态数组。

    - `__throw_length_error` → 这是安全检查，不是逻辑。

    - `label_5/goto` → 是编译优化产生的跳转

    - `_mm_loadu_si128` / `__m128i` → SIMD 优化，通常是拷贝

    - 遇到这些，直接看调用参数，或者干脆跳过。

2. 识别加密算法的“指纹”

    - S 盒（`63 7C 77 7B`）→ AES / Rijndael。

    - `Rcon`（`01 02 04 08...`）→ 密钥扩展。

    - 异或 \+ 加密 → CBC。

    - 64 字符自定义表 → Base64。
